# あるある投稿ネタの検討

X に投稿する「あるある」系の文章を考えるためのスキル。
過去に出したネタは `stock/` にジャンル別で保存してあるので、**必ず先に読んで重複を避ける**。

## 進め方

1. 依頼されたジャンルの `stock/*.md` を読む（ジャンルが曖昧なら直前の流れに合わせる）。
2. ストックと**テーマ・オチが重ならない**ネタを、指定の個数だけ考える。
   - 検討時は Web 検索などのツールを使わず、自分で考える（ユーザーの希望）。
   - 制度・税金・統計など**数字や事実を含むネタだけ**は、正確さを優先して確認してよい。
3. 下の「出力形式」で返す。
4. 返したネタを該当する `stock/*.md` の末尾に追記し、コミットして push する。

## 出力形式

- 冒頭に一文（例：「障害・炎上・理不尽をテーマにした会話形式のエンジニアあるある、追加の10選です」）。
- 各ネタは丸数字 + `ジャンルあるある「タイトル」` + 2〜4行の本文。
- 末尾に **伸びやすそうなのは〇つ**（理由を1行ずつ）。
- 数字や制度を含む場合は **事実の確認** を箇条書きで添える。

## スタイル

### 会話形式（いま一番よく使う）
```
エンジニアあるある「いい感じに」
顧客「いい感じにしてください」
SE「いい感じとは…」
顧客「見ればわかります」
```
- 話者は 顧客／SE／上司／PM／営業／新人／先輩／妻／母 など。心の声は（ ）で書く。
- 1行はスマホで2行に収まる程度（目安20字前後）。オチは最終行に置く。

### 2行型
```
傘を持って行った日は降らない
置いて行った日に降る
```

### 勉三系（質問でリプを集める型）
```
実際身長169cmだけど
170cmって答える人いますか？

私は184cmなんで185cmって言ってます
```
- 「〜な人いますか？」「何割ですか？」など、誰でも答えられる問いで終える。
- 自分の例でずらしてオチにすると強い。〇〇の部分はユーザーが実数を入れる前提で残す。

### 物申す系（制度の不満など）
- 3行前後。数字は公的統計や公式発表に基づくものだけ使い、事実の確認を必ず添える。

## 守ること

- 事実は正確に。不確かな数字は使わない。
- 特定の銘柄・ファンド名は出さない（投資系）。
- 特定の属性の人を見下したり、排外的だったりする煽りは作らない。
- ユーザーの実名は出さない。「私は〜」の体験談は「実際の状況に合わせて調整を」と一言添える。
- 性別役割など炎上しやすい表現には注意書きを付ける。
